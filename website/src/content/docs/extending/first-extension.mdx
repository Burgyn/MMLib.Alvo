:::tip[What you will achieve]
A delivery desk that refuses an order to a postcode the courier does not serve: one C# hook, its one registration
line in `Program.cs`, and one test that runs it through Alvo's real write pipeline. Every C# block on this page is
compiled by the repository's own tests, which also run the hook and the test (and the HTTP answer below, with this
page's `appsettings.json`); `Program.cs` is compiled, not run, and the shell and XML lines are not run.
:::

**Reach for C# only when the descriptor cannot express it.** A rule, a before-hook or a field's `validation` says most
things, and says them where the dashboard and the schema assistant can read them; a
[custom CEL function](/guides/custom-cel-functions/) adds a calculation. Asking the courier's service whether it delivers
to a postcode is neither: it is a call over the network, which no CEL expression can make. That is what a host hook is
for. [Where logic goes](/extending/where-logic-goes/) makes the same decision for every other case.

## Before you start

- **An embedded host**: an ASP.NET Core project (`Microsoft.NET.Sdk.Web`) that references `MMLib.Alvo` and a database
  driver, as in [Embed Alvo in ASP.NET Core](/start-here/embed/#1-reference-the-packages). No package is on NuGet yet,
  so that page shows how to reference a clone or a local feed. Host code does not run in the standalone image.
- **The descriptor** below, saved beside the project as `delivery-desk.alvo.json`:

## 1. Write the hook

<SourceExcerpt code={desk} from="using Microsoft.Extensions.DependencyInjection;" title="DeliveryDesk.cs" />

- **`Order` maps the entity.** `[AlvoEntity("orders")]` names it, and each property maps to its snake_case field
  ([Typed or CEL](/extending/typed-or-cel/#your-class)); a hook, a handler or a typed read works over it. You can have the build [generate the class from your descriptor](/extending/generated-types/) instead of writing
  it.
- **`PostcodeIsCovered` is a validate hook.** It runs before the write opens its transaction, so a network call holds
  no lock; it can refuse, but cannot change the row being written. `Invalid` refuses with your own code, at the field you name. Its constructor's
  services come from the host's container. The other phases, which run inside the write's transaction, are on
  [Validate and guard writes](/extending/write-hooks/).
- **`CourierAreas` is the real service**: an ordinary typed `HttpClient`. Alvo does not know it exists.
- **`AddDeliveryDesk` is the registration.** Most pages in this section end the same way: an `Add…` extension method
  on `IAlvoBuilder` that registers the code under a stable id, here `postcode-is-covered`. The id names the hook in
  refusals, logs, the [dashboard](/extending/extension-catalog/) and tests.

is answered `422` [`validation`](/reference/problem-types/#validation): its violation carries your code,

## 3. Test it

A test project on xUnit v3 (the test reads `TestContext.Current.CancellationToken`) that references
`MMLib.Alvo.TestHost` and your host project. `ALVO_CLONE` is where you cloned the repository; from a local feed,
`dotnet add package MMLib.Alvo.TestHost --prerelease` replaces the first `dotnet add reference`:

<Code code={testReferences.trimEnd()} lang="sh" title="Terminal (beside your host project)" frame="terminal" />

The `xunit.v3` package carries its own runner, so the project is an executable, as the repository's own test projects
are; and copy the descriptor into the test's output, so `AppContext.BaseDirectory` finds it:

```xml
<PropertyGroup>
  <OutputType>Exe</OutputType>
</PropertyGroup>
<ItemGroup>
  <None Include="../DeliveryDesk/delivery-desk.alvo.json" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>
```

The repository runs it on Microsoft.Testing.Platform, selected for `dotnet test` in its `global.json`
(`"test": { "runner": "Microsoft.Testing.Platform" }`).

<SourceExcerpt code={tests} from="using Microsoft.Extensions.DependencyInjection;" title="DeliveryDeskTests.cs" />

- **`AlvoTestHost.StartAsync` takes the same builder as `AddAlvo`**, so `.AddDeliveryDesk()` is the line your
  `Program.cs` has. It runs the production pipeline over an in-memory SQLite database.
- **The service is yours to replace.** The test registers a fixed list of postcodes in place of `CourierAreas`, so it
  never calls the network.
- **In process, a refusal is an exception.** `AlvoWriteRejectedException` carries the kind (`Invalid` here, which HTTP
  renders as `422`), your code and the field's pointer.
- **`Hooks.AssertRan`** counts the hook's runs by its id: both creates ran it, the refused one included.
