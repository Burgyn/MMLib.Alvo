# Slovak labels for the PR report

Read this **only** when the requested report language is `sk`. It exists so the
page's chrome is translated the *same way every time*: the fixed template's whole
value is that the maintainer never re-orients, and that value is lost if
"Forecloses" is "Zatvára" on one report and "Vylučuje" on the next.

**These translations are fixed.** Use them verbatim. Do not improve them per PR.

**When you need a string this file does not cover:** translate it as best you can
and then *name it in your `GAPS` line*, so it gets added here and the next report
matches yours. Silently choosing is how two reports come to disagree, which is
the whole failure this file exists to prevent.

`issue` stays English in the header chip: it is GitHub's own noun and the numbers
beside it are GitHub's. `draft` stays for the same reason.

The risk value is a **scale**, so it is the one word here that must never be
paraphrased — `stredné` every time, never `priemerné`, or two reports cannot be
compared.

The mutation gate's chip carries its own parenthetical because `nebežalo` alone
reads as an omission, and mutation not running on a PR is the *design*
(`CLAUDE.md`: Stryker runs post-merge on `main`). `main` keeps its spelling — it
is a branch name — and `post-merge` keeps its, being the repo's own term.

`renamed` is a distinct API tag from `zmenené`: a rename is the one change that
breaks a consumer's *source* while leaving the shape intact, so collapsing it
into "changed" hides exactly the consequence section 4 exists to report.

## The footer

Translate the boilerplate line as a unit, so it does not drift:

> `Generated by alvo-pr-report from …` → `Vygenerované cez alvo-pr-report z …`

The source list that follows it names files and tools, so it keeps their
spellings; only the connective words are Slovak.

`Breaking` stays English: it is the word the .NET ecosystem and this repo's own
CHANGELOG use, and "prelomová zmena" reads as a translation of a term rather than
the term.

## What must NOT be translated

Translating any of these makes the report wrong, not merely foreign:

- **Every identifier** — type, member, file, namespace, test method, project.
  `RecordValidator.TooLong` stays `RecordValidator.TooLong`.
- **Every literal the product emits** — violation codes (`read-only-required-field`),
  problem-type slugs, error messages quoted from the code, config keys
  (`Alvo__Auth__DevKeys__0__Secret`), descriptor keys (`maxLength`, `readOnly`).
- **Section 2's code blocks** — JSON, HTTP, SQL, C#. A caption above a block is
  Slovak; the block itself is verbatim. **One narrow exception:** a `//` comment
  *the report writes itself* to explain the demo is the report's own prose and is
  Slovak. A comment copied out of the repo is not — it is part of what is being
  shown. `alvo-pr-reporter.md` states the same exception in the same words; if
  they ever disagree, the block is verbatim.
- **Gate names and their output** — `ring0`, `dotnet format`, `CodeQL`,
  `CodeRabbit`, `E2E (compose + TeaPie)`, `needs-deep-review`, and any number or
  status they produced.
- **Mermaid node labels that name code** — a node reading `AlvoFrameworkTables.NamesFor(prefix)`
  keeps its spelling; a node reading `host does not start` becomes
  `host neštartuje`.
- **Spec, plan and issue titles** — quote them as written; the repo's docs are
  English and a translated title cannot be searched for.
- **Every message the product emits, wherever it is quoted** — a violation's
  `message` and `fixSuggestion`, a startup refusal, a validation error. This is
  the rule that is easiest to miss, because these read as prose and often sit in
  *your* prose rather than in a code block. They are public API (#122): a
  maintainer who reads a translated error message cannot grep for it, and cannot
  tell whether the wording he is judging is the wording that shipped. Quote them
  verbatim in English; put the Slovak gloss *outside* the quotation if the line
  needs one.
- **xUnit attribute names** — `Fact`, `Theory`. They are type names. Write a count
  as `3 × Fact`, `1 × Theory (3 prípady)`: the term stays, the counting word is
  Slovak.
- **`§0` principle names** — quote the principle as `docs/PLAN.md` spells it,
  then gloss it in Slovak if the chip has room.

## Register

Write the way the repo's own prose does: direct, concrete, no hedging, no praise
adjectives — the honesty rules do not relax in translation. Use the informal
second person (`tvoje rozhodnutie`, not `Vaše rozhodnutie`); this page has one
reader and he is the maintainer. Prefer a plain Slovak verb to a Slovak-inflected
English one where one exists and is not jargon (`odmietne`, not `refuseuje`), but
keep the English term where it *is* the domain's word (`commit`, `merge`,
`descriptor`, `endpoint`, `outbox`).
