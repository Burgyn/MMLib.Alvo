# The F5 admin dashboard — design prototype

A clickable prototype of the whole F5 admin dashboard: plain HTML, CSS and vanilla ES modules, no
build step, no framework. It exists so the dashboard's shape is settled before a Razor component is
written, and it is a **design artifact** rather than product code — nothing in `src/` may depend on
it, and it retires when the real dashboard lands.

The written design it implements, and deliberately departs from in places it records, is
[`docs/superpowers/specs/2026-09-18-f5-admin-dashboard-design.md`](../../superpowers/specs/2026-09-18-f5-admin-dashboard-design.md).
§4.6 of that document lists which of this drawing's decisions the design now carries.

## Run it

Serve **from the repository root**, not from this directory:

```bash
python3 -m http.server 8099
open http://127.0.0.1:8099/docs/design/f5-admin/index.html
```

The root matters: `index.html` links
[`src/MMLib.Alvo.Admin/wwwroot/alvo.css`](../../../src/MMLib.Alvo.Admin/wwwroot/alvo.css)
directly, so there is exactly **one** copy of the design system in this repository and no freshness
check to forget. An earlier version of this prototype carried a copy, which is a file that can
drift from the thing it claims to be.

Routes are hash-based. `#/notes` is the decision log — every deliberate choice with its reason,
including the review findings that were rejected and why.

**The static server publishes the whole checkout, `.git` included**, because that is what serving
one `alvo.css` from `src/` costs. It binds `127.0.0.1` and `http.server` sends no CORS header, so
it is not reachable from another machine or readable from another origin — but it is what would
make an XSS in this page serious rather than cosmetic, which is why the page treats an imported
descriptor as untrusted input and why `14-hostile-descriptor.spec.js` exists. Do not bind it to
`0.0.0.0`, and note that `reuseExistingServer` means a local run attaches to whatever already
holds port 8099.

## Test it

```bash
scripts/test-prototype              # every scenario, every matrix cell
scripts/test-prototype 05-layered   # one scenario
```

The suite is Node + `@playwright/test`, in [`tests/`](./tests). It is **in no ring**, for
`scripts/test-load`'s reason: the rings are `dotnet test` tiers and this stands up a browser over a
design artifact containing no .NET. Each scenario asserts three things separately — *does it work*
(no dead control, no thrown error, the state actually changes), *does it look right* (both themes,
1400 px and 375 px, nothing clipped or overlapping, no placeholder visible), and *is it usable*
(the move count against a stated budget, and the copy that explains what happened).

## The rule this prototype broke once

Every number, route, field facet and quoted refusal must be traceable to a file somebody actually
opened. The first iteration's worst defects all came from writing content from memory: refusal texts
were paraphrased, management routes lost their `/projects/{project}` segment, an access level
existed that the frozen schema refuses, and the engine was named in three places by an API that
cannot report one. That is why `generated/` exists and why nothing in it is hand-written.

Run `scripts/gen-prototype-fixtures --check` to prove it has not drifted.

## What has to be deleted with it

This prototype **retires when the Razor dashboard lands**, and three things retire with it. They
are listed here because two of them are wired into CI, and a generator for a directory that no
longer exists blocks a PR that has nothing to do with any of this:

| What | Where | Why it cannot be left behind |
|---|---|---|
| `scripts/gen-prototype-fixtures` | `scripts/` | it reads `src/` and writes `docs/design/f5-admin/generated/` |
| the `Prototype fixtures are not stale` step | `.github/workflows/ci.yml`, the `scripts` job | it is inside the **required** `Build & test` gate, so it fails a PR that never touched the prototype |
| the `Design prototype scenarios` job | `.github/workflows/ci.yml` | paths-filtered and not required, so it would simply stop running — but it would also stop being read |
| `scripts/test-prototype` and this directory | — | the suite and the drawing themselves |

The required step is deliberate while the prototype lives: rewording a refusal in
`UnhonouredFeatures.cs` **should** fail a required check, because a drawing that quotes it verbatim
has gone stale, and the fix is one command. It is exactly that property that makes it a thing to
remove on purpose rather than a thing to discover.
