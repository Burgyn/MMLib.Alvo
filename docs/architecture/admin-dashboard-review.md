# Architecture review — `src/MMLib.Alvo.Admin` as a foundation

Branch `f5/ai-agent` @ `98c9c6e`. Read-only review. `dotnet build src/MMLib.Alvo.Admin` → 0 warnings, 0 errors.

> This is the review that docs/superpowers/plans/2026-09-24-f5-admin-architecture-pass.md executes, task by task; committed here (Task 1) so it ships with the code it judges instead of staying workspace scratch.

## Executive summary

**It is a good foundation below the markup and a thin one at it.** The logic layer is strong: pure `Internal/*` helpers
(grid, form, ref labels, plan steps, diff) that are unit-tested (213 facts), a locked and evented `WorkingCopy`, a hard
package boundary (Abstractions only, pinned by an arch test), and a token layer that is correct: `light-dark()` declared
once, flat specificity, no literal colours, and contrast tests. The design system, though, is a **CSS system rather than a
component system**. Pages are assembled from `a-*` classes plus 156 inline `style=` attributes, and each page re-implements its
own lifecycle plumbing. The next feature will copy an existing page, not compose one. Five things limit extension most:

1. **Missing layout primitives.** There is no Panel/SectionHead (33 hand-rolled heads), no ListRow (`.a-listrow` exists, yet 12 inline-styled clones), no Field/Hint (41), no ChipGroup (11 sites, only 3 with `aria-pressed`), no Skeleton (15 inline heights) and no NotYetPanel.
2. **Page plumbing is copied, not shared.** Working-copy resolution is copied 8×, `Take` 5×, the `Changed` subscription with its disposed-guard 4×, the management-exception filter 10×, and a per-page `Refused`/`Fix` mapper 5×. There are 16 bare `catch (Exception)` with **no logging anywhere** and no `ErrorBoundary`.
3. **The public surface accretes and already bends the code.** About 40 components, every `[Parameter]` and every `[JSInvokable]` are package contract. `Entity.razor:202` avoids `OnInitialized` for that reason, and `StagedView` is passed through a cascade so it can stay internal. No policy says which components are supported. A host cannot add a page (the router scans only this assembly, and the navigation is internal and static).
4. **Routes are strings, and one of them collides.** There are 17 `@page` literals and 48 hand-interpolated hrefs. Entities named `preview` or `transfer` are valid descriptor names, but their schema screen can't be reached because a literal route wins.
5. **End-to-end tests are tied to copy and CSS.** 81 `:has-text` and 77 `.a-*` selectors mean a wording or class-name refactor breaks e2e. The keyboard map also emits `move`, `open` and `search` events that nothing subscribes to.

The fixes are proportionate. Add about six small primitives, one scoped `AdminSession` service, one error classifier, one interop service and route constants. No component library, CSS build or plug-in API is needed.

### Decisions while executing

- **F-21 — the breakpoint is pinned as two widths, not one.** `alvo.css` has one phone breakpoint, `720px`,
  and a second media width, `1100px`, where `.a-split` (a two-column screen) stacks its aside under the main
  column. That is a layout width rather than a device, and folding it into 720 would change how History and
  Rules look between the two. `StylesheetHygieneTests` therefore pins the set of media widths to exactly
  {720px, 1100px}, so a query drifting to 719px fails as the finding intends.
- **F-21 — a second consumer of the stylesheet.** The F5 design prototype (`docs/design/f5-admin`) links the
  shipped `alvo.css` and adds `proposed.css` on top. A rule only it renders (`.a-modal`, `.a-drawer`, and the
  old names `.a-page-title` and `.a-switcher-meta`) is kept and marked `/* prototype-only */`, the same way
  gallery-only rules are marked, and a test checks every class the prototype renders against the two files.
- **F-22 — `.a-row--gap-3` was removed, not kept as half of a pair.** It restated `.a-row`'s own
  `gap: var(--space-3)`, and no screen, the gallery included, ever used it. `.a-row--gap-2` stays.
- **F-9 — a screen cascades its `AdminProblem` to `ErrorPanel` rather than passing it.** The final review
  asked for an `AdminProblem? Problem` parameter, so the panel prints what the screen classified (with its
  site) instead of classifying the bare exception again. `AdminProblem` is internal and a component parameter
  must be public (CS0053), so the screen wraps the panel in `<CascadingValue Value="_problem">` and the panel
  reads it through a private `[CascadingParameter]`, the pattern `StagedView` and `RecordFormScope` already
  use. The raw-exception parameter is renamed `Problem` → `Fault` and kept only for the layout's
  `ErrorBoundary`; `ErrorPanelText` is the projection, and it is what the tests pin.
- **F-3 / F-19 — the hand-written `a-section-title` / `a-section-sub` pairs moved to `__title` / `__sub` in
  one pass, not to a new primitive.** They are title-over-sentence pairs in cards and callouts with no
  section head around them, and the rule was already the same rule; a `<Heading>` component would have been a
  public type for a two-span shape. The hyphenated spelling is kept only as a `/* prototype-only */` alias,
  because the design prototype still renders it.
- **Sheet focus — the panel's focus is sent before the scroll lock is awaited.** A field inside the sheet
  that takes focus on its first render (`FocusOnRender`, reused for the field sheet's Name box) then gets it
  second and keeps it; awaiting the lock first let the panel take focus back.

### What is good and must be kept

- **The boundary.** `MMLib.Alvo.Admin.csproj` references Abstractions and nothing else, and `BoundaryArchitectureTests` pins it, including "only the seven, plus what Blazor forces".
- **Pure, tested helpers.** `GridQuery`, `GridColumns`, `GridCell`, `RefLabels`, `RefPicker`, `FormValue`, `RecordDraft`, `PlanStep`, `LineDiff` and `EntityTabs` hold no Blazor, and each has its own suite. This is the reason the pages are big but not untestable.
- **`WorkingCopy` concurrency.** One `Lock` is taken, `Changed` is raised outside it, and handlers marshal through `InvokeAsync`. `WorkingCopyStore` is per user, keys anonymous callers out, and evicts idle copies.
- **The token layer.** `light-dark()` is declared once, and the explicit theme overrides it in both directions. `DesignTokenTests` (WCAG AA per pair and theme), `ComponentLayerTests` (no literal colour, no duplicate selector, focus ring, reduced motion) and `GalleryTests` (the gallery links the shipped file) all run against it. Specificity is flat: the maximum is (0,3,0), and only 13 selectors are ≥ (0,2,1).
- **Shared overlays and header.** `Sheet` is one overlay with two shapes and owns Escape, focus and scroll lock. `PageHeader` is used on 14 of 14 routes.
- **Theme before hydration.** The pre-hydration `alvo.js` applies the theme with no flash, and the ES-module bridge uses token-keyed subscriptions (a correct design).

## Refactoring plan

Each step is its own PR and keeps `scripts/test-admin-e2e` green. The order is chosen so that no step is redone by a later one.

1. **Settle the public-surface policy and the parameter vocabulary** (F-10, F-7, F-27). Add `@attribute [EditorBrowsable(Never)]` in `_Imports.razor` and a README/AssemblyInfo statement of what is supported. Choose the names the primitives will use. Correct the two stale remarks. *S. The baseline gains only the attribute.*
2. **Error policy** (F-9). Add `AdminProblem.From`, `ILogger<T>` in the pages that catch, and `<ErrorBoundary>` around `@Body`. Replace the 10 filters, the 16 catch-alls and the 5 fix mappers. The panels render the same text, so e2e is unaffected. *M.*
3. **`AdminSession`** (F-8, F-17). Resolve the caller and the working copy, provide `Follow(...) → IDisposable`, and add a per-component cancellation helper. Convert the 8 sites and remove the `DataGateway Caller` injections. *M.*
4. **Routes** (F-12, F-14). Add `AdminPaths` and move Preview and Transfer off `schema/{EntityName}`, with an e2e scenario for an entity named `preview`. Make tab dispatch go by slug. *S.*
5. **Primitives** (F-1..F-6, F-22). Add `Panel`, `ListRow`, `Field`, `ChipGroup`, `Skeleton` and `NotYetPanel`/`Refusal` in `Components/DesignSystem`, and show each one in the gallery. Adopt them **one page per PR**, starting with Access, SchemaList and Preview (the most inline styles). Add `.a-hint`, `.a-spacer`, and the `@layer` declaration (F-20). *M for the primitives, then S per page.*
6. **Break up the large components** (F-13, F-26). Add code-behind partials, the `FieldFacets`/`HookBuilder` helpers in `Internal` with unit tests, `RecordGrid`, `PersonRow` and `NavList`. *M.*
7. **`WorkingCopy` split** (F-16). Add the `Edit` primitive and partial files per block, and decide on `Forget`. The existing suites are the net. *M.*
8. **Interop service** (F-18). Add `AdminInterop`, then build j/k/Enter row navigation or drop the dead events and `aria-selected` CSS. *S–M.*
9. **Cache invalidation across circuits** (F-15). *S.*
10. **CSS hygiene** (F-19, F-21). Normalise names as pages migrate, remove dead selectors, add z-index tokens and pin the breakpoint. *S.*
11. **E2E selector policy** (F-23). Add the guard test, then migrate as scenarios are touched. *M, gradual.*
12. **Feature folders** (F-25). One mechanical move, last, because it moves every component namespace in the baseline once instead of repeatedly. *M.*

### Considered and rejected (deliberately not to do)

- **A component library** (MudBlazor, Fluent UI). Design D1 rules it out, and the token system and tests are the asset. A library would bring a second theme to keep in step.
- **Blazor CSS isolation (`.razor.css`) or any CSS build step** (Sass, Tailwind, PostCSS). The gallery and hosts depend on global `a-*` class names, and `AlvoAdminAssets.StyleSheet` promises one file. Isolation rewrites selectors with scope attributes and adds a second bundle a host must link.
- **Splitting `alvo.css` into several `<link>`ed files.** Load order would become a host concern, and three tests parse the one file. `@layer` inside one file gives the ordering guarantee without that cost. Revisit at about 3k lines using `@import`.
- **An `AdminPageBase` base class for the lifecycle plumbing.** The base class would have to be **public** (an internal base class of a public Razor component is CS0060), which turns the plumbing into contract. Use an injected service plus small `IDisposable` helpers instead.
- **A generic `DataGrid<T>` with column definitions**, or a templated `<Loadable>` state-machine component. There is one grid today, and the pages' states (refused / out-of-scope / pending entity / empty-by-RLS) differ in meaning, not just in shape. Extract `RecordGrid` now and generalise when a second grid appears (API keys, the F7 audit log).
- **A host extension API** (`AdditionalAssemblies`, a public section registry, palette providers). No consumer exists, and every type in it would be permanent contract. Keeping `AdminNavigation` as the single source keeps that seam cheap to add later.
- **A state-management library** (Fluxor or similar) **or a message bus** for cache invalidation. `WorkingCopy` + `Changed` + a navigation-time invalidate is enough.
- **bUnit component tests now.** The humble-component pattern already keeps logic unit-tested. Reconsider for the primitives only if their accessibility behaviour starts regressing.
- **Big-bang renames of CSS classes.** Rename only as a page migrates to the primitives, so every PR stays reviewable and e2e stays green.
