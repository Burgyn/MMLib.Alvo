# F5 AI agent (#29) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ship the assistant the dashboard design deferred — a secret store it can keep a model key in, a configurable AI connection reported by `GET {m}/info`, and an agent whose tool set cannot apply anything.

**Architecture:** `ISecretStore` is a new port in Abstractions with two implementations (configuration-backed read-only in the core; AES-GCM encrypted rows in the EF adapter), layered configuration-over-database. The AI connection resolves under the same precedence and is reported, without its endpoint, on `GET {m}/info`. A new `MMLib.Alvo.Ai` package holds Microsoft Agent Framework and exposes `IAlvoAssistant` (declared in Abstractions), whose five tools are all `IAlvoManagement` members — four reads and one `DryRun: true` apply. The dashboard renders the agent's proposal into the existing working copy and the existing diff; the existing Apply is the only writer.

**Tech Stack:** net10.0, xUnit v3 on Microsoft.Testing.Platform, Shouldly, NSubstitute, `Microsoft.Agents.AI`, `Microsoft.Extensions.AI`, `Microsoft.Extensions.AI.OpenAI`, Blazor Web App (server-interactive), Microsoft.Playwright.

**Spec:** `docs/superpowers/specs/2026-09-22-f5-ai-agent-design.md` — read it before Task 1 and re-read the section a task cites. The plan argues from it and never restates its reasoning.

## Global Constraints

- **Target framework `net10.0`**, SDK pinned in `global.json`. Never add a `TargetFramework`, `Nullable`, `ImplicitUsings` or `LangVersion` to a new `.csproj` — `Directory.Build.props` owns them, and `MMLib.Alvo.Conventions.Tests` fails a project that redeclares one.
- **Central Package Management**: every new dependency's version goes in `Directory.Packages.props`; a `PackageReference` carries **no** `Version`.
- **Licensing**: Apache-2.0 core. `Microsoft.Agents.AI` and `Microsoft.Extensions.AI*` are MIT — allowed. No MediatR, no FluentAssertions; assertions are **Shouldly**.
- **XML doc comments are required on every public member** of a shipped project.
- **Zero inline comments explaining what code does** — extract a named method or constant instead. A `/*  */` block stating a non-obvious *why* is the only survivor, and the repo's existing ones are the model.
- **Methods stay under ~25 lines**; extract by default.
- **English only** in code, literals, log and skip messages.
- **Write `.cs` files with the Write/Edit tools, never with a shell heredoc or python** — the repo's `.cs` files are UTF-8 **with BOM and CRLF**, and a shell-written file fails the pre-commit `dotnet format` check. After any bulk edit run `dotnet format` before committing.
- **`scripts/test-ring0` after every step that touched code**; `scripts/test-ring1` when a task closes; `scripts/test-ring2` before the PR.
- **A secret's value must never be logged, returned by `ToString`, placed in `ManagementInfo`, or written into a descriptor.** Every task that touches a secret ends with that assertion still passing.
- A background `MMLib.Alvo.Host` may be running from this session (scratchpad `alvo-phone`); if a build fails to write `MMLib.Alvo.Host.dll`, stop that process first.

/// <summary>A value written is the value read back, byte for byte.</summary>
[Fact]
public async Task Get_returns_what_Set_wrote()
{

    await store.SetAsync(Name("one.two"), "  a value with spaces  ");

    (await store.GetAsync(Name("one.two"))).ShouldBe("  a value with spaces  ");
}

/// <summary>An unknown name is absence, not an error — a caller asking whether a secret exists is ordinary.</summary>
[Fact]
public async Task Unknown_name_is_null_rather_than_an_exception() =>
    (await CreateStore().GetAsync(Name("never.written"))).ShouldBeNull();

/// <summary>A second write replaces the first; a store is a map, not a history.</summary>
[Fact]
public async Task Set_replaces_an_existing_value()
{
    var store = CreateStore();
    await store.SetAsync(Name("k"), "first");
    await store.SetAsync(Name("k"), "second");

    (await store.GetAsync(Name("k"))).ShouldBe("second");
}

/// <summary><see cref="ISecretStore.DeleteAsync"/> reports whether anything was removed, so a caller need not read first.</summary>
[Fact]
public async Task Delete_reports_whether_it_removed_anything()
{
    var store = CreateStore();
    await store.SetAsync(Name("k"), "v");

    (await store.DeleteAsync(Name("k"))).ShouldBeTrue();
    (await store.DeleteAsync(Name("k"))).ShouldBeFalse();
    (await store.GetAsync(Name("k"))).ShouldBeNull();
}

/// <summary>A listing carries names and no values — a bulk read is what an exfiltration needs and nothing in the build wants.</summary>
[Fact]
public async Task ListNames_returns_names_and_no_values()
{
    var store = CreateStore();
    await store.SetAsync(Name("a.one"), "secret-value");
    await store.SetAsync(Name("b.two"), "another");

    var names = await store.ListNamesAsync();

    names.Select(n => n.Value).OrderBy(v => v).ShouldBe(["a.one", "b.two"]);
    names.Select(n => n.ToString()).ShouldNotContain("secret-value");
}

/// <summary>A read-only store refuses a write rather than accepting it silently.</summary>
[Fact]
public async Task A_store_that_cannot_write_says_so_and_refuses()
{
    var store = CreateStore();
    if (store.CanWrite)
    {
        return;
    }

    await Should.ThrowAsync<InvalidOperationException>(
        async () => await store.SetAsync(Name("k"), "v"));
}

private static SecretName Name(string value) => SecretName.Parse(value);
